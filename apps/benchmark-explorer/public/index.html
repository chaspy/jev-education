何を実験したのか

授業に合う問題を探すとき、
Jevを足す意味はある？

先生が「今日の授業の復習問題を探したい」と依頼する場面を作りました。普通の検索と条件チェックに、AIによる内容の判断を加えると、教材の選び方が良くなるかを調べています。

生徒の間違いの原因を当てる実験とは別です。今回は、先生の依頼と教材の内容を照合しました。

1 / 仮説

言葉が似ている教材より、目的に合う教材を上に出せるのでは？

先生：「分数を含む方程式で、全ての項に同じ数を掛けて分母をなくす操作を練習させたい。2分以内の問題を探して。」

検索は文章の似た教材を集められます。しかし、同じ「方程式」の問題でも、練習する操作は違います。

教材A

3x = 12 を解こう。

両辺を3で割る練習。方程式の問題ですが、分母をなくす操作はありません。

教材B

x/2 + 3 = 7 の両辺に2を掛けると？

分母をなくすときに、全ての項に掛けられるかを確認できます。

検証した仮説先生の授業内容と教材本文をJevに渡せば、候補の中からBのような教材を先頭に上げられるのではないか。

2 / 実験方法

同じ依頼・同じ候補で、Jevを加える前後を比べた

用意したもの

自作の数学教材40件と、架空の先生の依頼34件。教科書の範囲、指導要領、授業計画、実際に説明した内容、既習事項、形式、時間を用意しました。

実在の先生の依頼や、市販教科書・スタディサプリの教材は使っていません。

Jevに聞いたこと

「この教材は、先生が今回練習させたい内容に直接合っていますか？」

教材ごとに『合う』と見込む値を0〜1で返してもらいました。問題を生成したり、生徒の理解度を推測したりはしていません。

  1. 検索：教材40件から、文章の一致を使って12件に絞る。
  2. 条件チェック：時間オーバー、形式違い、必要な知識が未習の教材などをコードで除く。
  3. 比較：残りを検索順位のまま見せる場合と、Jevの判断で並べ替える場合を比較する。

Jevに渡す候補を増やしたわけではありません。同じ候補の順番を変えることに価値があるかを比べました。

3 / 何を「正解」としたか

実験前に、こちらで「合う教材のリスト」を作った

それぞれの依頼について、①目標と同じ学習項目を扱い、②時間・形式・既習事項などの条件を満たす教材を正解としました。複数の教材が正解になる依頼もあります。

さきほどの例なら、Bは「分母を払う」という項目に属するので正解。Aは「等式の性質」の項目なので、この採点基準では対象外です。

大事な限界このリストは僕が作った採点用の答え合わせ表です。先生に妥当性を確認してもらったものではありません。以前「仮ラベル」と呼んでいたのは、この表の判定です。

「対象外」は悪い教材という意味ではありません。今回の依頼に対し、この採点方法では正解に数えなかったという意味です。後で、この採点方法自体が粗い例も見つかりました。

5 / 全体の結果

適合教材あり24件 / 該当なし10件

34件の依頼のうち、こちらの採点表で正解教材があるのは24件。残り10件は「この教材集には合うものがない」依頼です。まず24件について、最初に出した教材が採点表の正解に入っていたかを数えました。

主な比較結果検索＋条件チェックでは19 / 24件。Jevで並べ替えると21 / 24件。最初の教材が正解になる依頼が、2件増えました。
実験時の固定条件での成績
方法最初の教材が採点表の正解3件以内に採点表の正解条件違反該当なしへの誤推薦
追加実験：自信が低い候補を隠すとどうなる？

低い確率の教材を隠すと、どうなる？

保存したJevの判定値を使って、表示する教材を変えます。APIは呼びません。実験で使った下限は0.65です。高いほど表示を絞りますが、使える教材も隠す可能性があります。

費用は入力100万tokensあたり$0.042、出力無料で推定。時間は当時のAPI実測です。このページの表示速度ではありません。40教材の小規模実験なので、2万教材への効果は未測定です。

6 / 結果をどう読むか

分かったことは、3つある

01

まず、条件チェックがよく効いた

検索だけでは、最初の教材が正解だったのは6件。時間・形式・前提知識をコードで確認すると19件になりました。大きな改善はAIではなく、明示的な条件を処理した効果です。

02

Jevには小さな追加効果があった

条件チェック後の19件が21件になりました。ただし、3件以内に正解を含む依頼の数は21件のまま。正解を新しく見つけたというより、既に候補にあった正解を先頭へ動かした効果です。

03

正解が検索から漏れると、Jevでは救えない

3件では、正解教材が検索上位12件に残りませんでした。Jevに見せなかった教材は選べません。この実験では、検索方法を改善する余地もありました。

注意

答え合わせ表にも、直すべき点があった

「かっこを含む方程式の練習」という依頼に、かっこのない「2x + 4 = 10」も同じ単元だから正解としました。Jevは低く評価しましたが、これは採点表の方が粗い可能性があります。

7 / 事業としての示唆

安く速く候補を並べる仕組みは動いた。役立つかの判断はまだ先。

JevのAPI処理は中央値約0.25秒。今回の全実験の推定費用は約0.0022ドルでした。少数の検索候補について内容を判定する処理としては、今回の規模で動作を確認できました。

ただし、先生が探す時間を短縮できた、実際の教材選びが87.5%正しい、とは言えません。先生は評価に参加しておらず、扱った教材も40件だけです。

  1. まず採点を確かめる：先生に文脈と教材を見てもらい、「この授業で使えるか」を評価してもらう。
  2. 次に検索の取りこぼしを減らす：適切な教材を候補に残せる検索と、Jevによる並べ替えを分けて評価する。
  3. 最後に業務上の価値を測る：先生が教材を決めるまでの時間と、選んだ教材の採用率を比較する。
今回の結論Jevを足す価値の小さな手掛かりは得られたが、採用を決める根拠にはまだ足りない。次に必要なのは、モデルを調整する前に、先生が納得できる答え合わせ表を作ることです。

実験の作り方

  1. 公開自作教材から、説明10件・確認問題10件・練習問題20件を用意。
  2. 教科書範囲、指導要領、授業計画、実施内容、既習事項、目標、形式、時間を記した架空の授業ケースを作成。
  3. 8件を開発用、34件を評価用に分割。同じ単元のケースは両方に混ぜず、今回は調整に使わなかった。
  4. 実験用の採点判定・検索・質問・足切り値をcommitで固定してから、jev-1.13.0を実行。
  5. 検索だけ／条件処理／Jevの並べ替え／確率で非表示、の4条件を同じ候補で比較。
