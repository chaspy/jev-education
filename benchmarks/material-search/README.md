# 授業文脈に合う教材の検索・適合判定

既存の公開デモ教材40件を対象に、教師の授業文脈に合う教材を検索する技術的な予備実験。
過去の「誤答から隠れた生徒設定を当てる」課題とは別。授業の目標・実績・既習範囲・条件を入力し、
教材本体がその目標に直接対応するかを評価する。

**教師が付けた正解データではない。** 授業ケース・タグ・時間・正解基準はAI補助で作成した。
著者の目標タグ一致と明示的条件を操作的な正解とする。現場の採用率や教育効果の実証とは区別する。

## データと分割

- 公開済み `apps/learning-path/public/content.js` の10単元から、説明10・確認問題10・練習問題20。
- 自作教材・新規ケースはCC BY 4.0。企業・学校・生徒のデータ、市販教科書本文は使わない。
- 教科書欄は架空の「公開デモ教材集 v1」。公式教科書対応を装わない。
- 指導要領本文は既存 `curriculum.json` のCC BY 4.0資料を再利用。出典は学習指導要領LOD／元資料文部科学省。
- 教師ケースは42件。2単元8件をdev、残り8単元32件＋未収録分野2件をtest（34件）に固定。
- 同一単元の条件違いはsplitをまたがない。検索の文書集合は共通で、未知教材への汎化評価ではない。
- devもtestもプロンプト・閾値の調整には使用しない。
- 文脈は教科・学年・教科書範囲・指導要領・計画・実際の授業内容と例・既習知識・課題の目標・形式・時間。
- 既習事項はデモ独自の前提関係グラフから付与。確認1分・練習2分という時間は仮定で、実測ではない。

同じ目標でも「練習問題」「説明」「1分の確認」「1分の説明」と条件を変える。
1分の説明の要求は該当教材が存在しない。さらに幾何・比例の2ケースも教材自体が未収録。
全部でtestの24件には適合教材があり、10件は該当なし。
授業例と教材内容は一部共通し、独立した実世界の検索要求ではない。

## 正解基準

1. 教材の主な学習操作のタグが、授業の課題目標のタグと一致する。
2. 学年・教科・形式・1教材の所要時間・前提知識の条件を満たす。

1と2を満たす全ての教材を正解として採点し、1教材に限定しない。
タグ・正解ラベルは評価専用。モデル入力から隠し、教材本文・模範解答・タイトルは渡す。
単元全体を俯瞰した補助教材としての価値や、先生ごとの好みはこの基準で扱わない。
タグの妥当性と文脈の自然さは教師のレビュー前であり、今後の評価データにそのまま流用しない。

## 比較方法

同じ授業文脈を使う強めの検索ベースラインを用意する。
BM25（日本語文字2-gram、k1=1.2,b=0.75）の検索文は目標＋授業実績＋指導要領本文。
対象文書は教材のタイトル＋本文。上位12件を候補として固定。

- `retrieval`：検索上位3件。
- `filtered`：上位12件にメタデータ条件を適用し、元の順位で上位3件。
- `jevRanked`：同じ条件通過候補をJevの適合確率で並べ替えて上位3件。
- `jevSelected`：同じ並べ替えで適合確率0.65以上のみ、最大3件。

時間・形式・前提タグなど、コードで分かる条件は共通フィルターで処理する。
Jevは内容の意味的な適合をNoulで判定。候補ごとに独立の質問を作り、授業ケース単位で1APIリクエストにまとめる。
Noulはyesの確率1つを返し、Choiceのような独立したconfidenceはない。
候補が全て条件違反ならAPIを呼ばず「該当なし」。検索が落とした教材はJevで復活させない。
タイブレークは元の検索順位。閾値・候補数・評価方法は実行前に固定。

## 指標

- 候補Recall@12：全正解教材のうち検索候補に残った割合。Jev以前の検索の取りこぼしを測る。
- Top-1・Success@3・nDCG@3：適合教材が存在する24要求だけで算出。
- 表示適合率：全表示教材に占める正解教材の割合。表示を減らせば上がり得るためSuccessと併記。
- 条件違反件数：表示上位3件に明示的条件違反の教材が含まれた数。
- 該当なし誤推薦率：該当なし10要求で1つでも提示した割合。時間で除外できる8件と意味的に不適合な2件を分ける。
- 検索・フィルターのローカル時間、API時間、両者の合算時間を実測。中央値・p95、token使用量・推定費用を保存。

初回の分類実験とは指標もタスクも異なる。2万件環境の応答時間・検索精度を推定しない。
34件は単元・文脈を共有する少数のケースで、有意差や普遍的な性能は主張しない。
教師の教材選択時間、修正量、採用率、学習効果は今回は測れない。

## 実行

```sh
npm run benchmark:material-search:prepare
npm test
# .envのTYPESAFE_API_KEYを使用。実API課金あり
npm run benchmark:material-search
```

モデルはjev-1.13.0。入力$0.042/M、出力無料で推定費用を計算。
原データ・全リクエスト・ソースのハッシュを実行前に保存し、途中の変更・再試行・出力修復はしない。
HTTP／形式エラーがあれば停止。`calls.jsonl`に生のAPI出力、`predictions.jsonl`に全手法の候補と評価を残す。
結果フォルダの`summary.json`で集計。キーや認証ヘッダーは保存しない。

今回の設計は[TypeSafeのreranking例](https://docs.typesafe.ai/cookbooks/rerank_typesafe)と
[Noul仕様](https://docs.typesafe.ai/primitives/noul)を参照。モデルの入力状態・質問をログで確認できる。
