# 追加問題による再判定の模擬実験

これはMaEの再測定ではなく、事前に固定した架空生徒に対する別実験です。
MaEの55択・58.3%とは直接比較できません。実際の生徒での改善や学習効果も示しません。

## 実験条件（API呼び出し前に固定）

- 正解設定は分配法則、移項・減算の符号、等式の片辺だけの操作、分配＋符号の両方、一時的ミスの5種類。
- Jevには上記5候補と「証拠不足・候補外」を提示。
- `a(x + b) = c` 型の自作3問題、5設定、最初の誤り方2種類、追加回答の条件3種類で90シナリオ。
- 最初の誤り方は「設定に対応する手続きの誤り」と「設定によらない一時的計算ミス」。すべて最初の答案は不正解。
- 設定に対応する初回の誤答は、分配 `(c-b)/a`、符号 `c/a+b`、片辺操作 `c/a`、複合 `(c+b)/a`、一時的ミス `c/a-b+1`。
  複合は分配の掛け忘れ後に符号も取り違える手続き。設定によらない計算ミスは全員 `c/a-b+2`。
- 誤答は最終数値のみ。途中式・設定・正解ラベル・誤答生成の式はJevに渡さない。
- 各生徒の3つすべての追加問題への回答を `../data/synthetic-followup.json` に先に固定。
- ノイズなしでは苦手な技能の問題を間違え、他は正解。
- 「偶然正解」は苦手技能1つを正解に反転。「不注意」は習得済み技能1つを誤答に反転。
  該当技能がない場合は反転なし。どの技能を反転するかは元問題番号で固定。
  3条件は同じ生徒設定に対する感度分析であり、実社会での出現率ではない。

## 推論フロー

1. 初回の問題・模範解答・誤答のみを渡す。Jevが設定を推定し、独立のChoiceで確認問題を選ぶ。
2. 選ばれた問題への固定済み回答を参照する。選択段階では回答・生徒設定にアクセスしない。
3. 元答案と追加の問題・模範解答・答案を渡し、同じ基準で再判定する。初回の推定結果は渡さない。
4. 全90シナリオについて追加前後を比較。初回分類が外れた例だけを選ばない。

確認問題は展開、減算による移項、等式を保つ右辺の操作の3問。
問題文と模範解答はモデルに提示されるが、未選択問題への架空生徒の回答は渡らない。
「証拠不足」を含むTop-1を全件で集計（証拠不足は潜在設定との不一致扱い）。
保留率・回答した分の正答率も併記する。保留した判断自体が教育的に誤りという意味ではない。

比較ルールは同じ確認問題について「誤答→確認対象の技能」「正答→一時的ミス」。
複合原因を表せず、強力な比較手法ではない。初回答案は利用しないため、Jevとの差は
意味理解だけでなく元答案を併用する違いも含む。ルール超えだけでJevの必要性は示せない。

## 再現と限界

```sh
npm run benchmark:simulation:prepare
npm test
# .env の TYPESAFE_API_KEY を使う。実API課金あり。
npm run benchmark:simulation
```

同じJSONリクエストは実行内で1回だけ呼び出し、全シナリオで同じ結果を共有する。
特にノイズ3条件は同じ初回判定を使う。90件の独立な生徒サンプルやモデル反復試行ではない。
全分岐のリクエスト、データ、コードのハッシュを実行前に保存。結果を見た調整は行わない。
API障害時は途中ログを残し停止し、再試行・代替予測をしない。
実行結果の `calls.jsonl` にraw request/response、`predictions.jsonl` に各条件の参照IDを保存。
時間と料金は実際に呼び出した分のみ。追加問題を人が解く時間は含まない。

これは作者が仮定した誤答手続きを識別する検証。手続きや正誤反転の仮定に恣意性がある。
潜在設定が違っても全く同じ答案になる場合があり、1問追加しても一意には判別できない。
生徒モデルを採点基準としながら観測上の識別不能も誤分類に数えるため、必ず満点を出せる課題ではない。
教科専門家によるレビュー前。教材の戻り先や実際の理解向上は評価していない。
